# 参考 DeepTutor：借什么、不借什么（2026-11-15）

## 定位

DeepTutor：通用 AI 学习平台，强在 living book、RAG、练习、workspace、渠道、多用户。
TermFinale：期末交付编译器，强在真题/蓝图/整卷/审计/讲义/页级覆盖。

**不能做第二个 DeepTutor。** 要做“带学习闭环的期末交付器”。

## 可以借（P0）

| 功能 | 她怎么做 | 我们怎么加 | 价值 |
|---|---|---|---|
| 页级问答 | Page Chat，锚定当前页 | 讲义每页右下角问 AI，回答带页码/引文，可跳回 | 让讲义不是死文档 |
| 块状讲义 | text/quiz/flashcard/callout/figure/interactive | 讲义增加 quiz/闪卡/重点卡/图块，答案可点开 | 图文并茂 + 主动回忆 |
| 章节提案 + 成本 | 生成前审阅大纲、逐章预估、先第一章 | DIY/长书确认卡显示章节、页数、时间、费用；可先跑一章 | 控成本，不黑箱 |
| 题库/错题/复习 | 导入 XLSX/CSV、错题、间隔复习 | 已有题库/错题，补“下次复习日/今日复习” | 考前闭环 |
| 工作区 | 每门课独立 workspace | 课程=资料+讲义+提取+卷+错题，多资料独立 | 解决互相污染 |

## 可以借（P1，不阻塞发布）

- RAG 引擎接入：PageIndex / LlamaIndex / WeKnora，别自己造；
- 闪卡/间隔复习算法；
- 导出 Markdown/Anki；
- 页面级引用跳转；
- 多用户/渠道：等有人用再说，不现在做。

## 不要借

- IM 渠道（微信/QQ/Telegram）；
- 多用户权限、管理台；
- MCP/Skills 市场；
- Manim 动画、3D；
- 通用聊天/角色广场；
- 自建向量库/图数据库。

这些是平台工程，不是我们的胜负手。

## 只有我们能做（必须强化）

1. **往年真题变式**：原题→变式→答案→来源；
2. **考试蓝图**：题型/分值/章节权重/时间；
3. **整卷模考 + 计时 + 交卷判分**；
4. **答案独立审计/冲突复核**；
5. **页级覆盖 + 拒收原因**；
6. **可打印冲刺讲义 PDF/Word**。

## 产品结构

上传资料/真题
→ 资料工作区（独立）
→ 章节提案 + 成本（可只跑一章）
→ 冲刺讲义（块状，可问、可测）
→ 考试蓝图
→ 整卷模考
→ 错题/薄弱点
→ 变式二刷
→ 导出 PDF/Word/Anki

## 轮次影响

原 24 轮不重排；把 P0 塞进已有轮次：

- 第 11–12 轮：资料工作区 + 四模块独立（已有）；
- 第 14 轮：整卷模考 + 错题复习（已有题库，补计时/复习日）；
- 第 20–22 轮：UI 里加页级问答、quiz/闪卡块；
- 第 19 轮：章节提案 + 成本确认卡。

**不增加总轮数；砍掉低价值 UI 装饰，换这些。**

## 判断

- 只加通用聊天/多用户/渠道：是平替，输；
- 加“页级问答 + 块状讲义 + 题库复习 + 工作区”，同时保留真题/蓝图/整卷/审计：不是平替，是“学习闭环 + 考试交付”；
- 最终必须有 benchmark：同一份资料，DeepTutor 做学习，我们做整卷；比“谁能交付一场期末考”。

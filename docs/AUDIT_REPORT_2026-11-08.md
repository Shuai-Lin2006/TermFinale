# TermFinale 真机 E2E 评估报告（2026-11-08）

> 本文是实测报告，不是功能清单。测试对象：本机正在运行的 TermFinale v0.3.0（Electron + FastAPI，127.0.0.1:8903）。
> 测试资料：本机已有 `高数类测试·35页.pdf`（35 页，545KB）。
> 测试方式：Playwright 驱动 Microsoft Edge 真实点击页面 + 直接调用同一后端 API 做长任务与数据核对。
> 数据安全：没有重置数据库、没有删除原资料、没有点“清除全部数据”。审计课程 `审计课程_20261108`（id=9002）是本次新建的测试课程，资料是上传副本，不碰原文件。报告完成后，审计课程、其上传副本和桌面测试输出已清理；`docs/evidence/audit_2026-11-08/` 保留证据。正式课程 1 和用户数据未动。
>
> **2026-11-09 标准更新**：封面/标头、目录/摘要/分节出处/结语/页脚、150 页覆盖、AI 无处不在等新要求，以 `docs/ULTIMATE_FORM_LOCKED.md` 为准；本报告按 2026-11-08 的 150 页口径记录，实测结论不变。

## 0. 结论摘要

### 0.1 一句话结论

**当前版本不是“终极形态”，也不是“接近完成”；它是一个能跑通部分流程的功能演示壳。核心内容管线不可信：讲义生成了模板垃圾，提取在 0% 覆盖时仍判通过，试卷答案算错但判分系统把它当正确答案，逻辑分析直接空结果，英语界面大量中文残留。**

### 0.2 最严重的 10 个问题（P0）

| # | 问题 | 实测证据 | 影响 |
|---|---|---|---|
| 1 | 讲义生成是模板拼接，不是成文 | 4 页资料只生成 677 字；两章标题完全相同；每段固定句“这句是资料里的直接结论…”；正文出现 P.1/P.2 | 学生读不到“讲解”，更做不了课后题 |
| 2 | 讲义大纲兜底把资料头当章名 | 缓存大纲两章都叫 `【重点资料·权重3：高数类测试·35页.pdf】`；`core/generate/outline.py` 的 `_page_head` 没有过滤资料头 | 章节结构从源头就是错的 |
| 3 | 提取 points 在覆盖率 0%、0 条页码时判“通过” | 4 页全部未引用（pages_missing=[1,2,3,4]），`validation.ok=true`、`quality.passed=true`、任务状态 done | “任务成功=内容通过”的典型漏洞 |
| 4 | 试卷答案算错，判分系统仍判对 | mock 第 2 题：方程 `u²+tan(v)=e^u`，u(0)=0、u'(0)=2，正确答案 v'=1；系统答案 A=-2，选项里没有 1；练习判分显示 2/2 | 会把学生教错，且无法发现 |
| 5 | 试卷选项重复/无正确选项仍判通过 | variant 第 1 题 A 与 C 等价；第 2 题解析自述“无选项匹配该结果”，仍按 C 计分 | 题目本身不可做 |
| 6 | 逻辑分析直接空结果 | 3 次尝试、4 秒，`生成结果为空` | 四类任务之一完全不可用 |
| 7 | 语言策略与最新要求相反 | 生成 prompt 写“STRICT ENGLISH ONLY / 必须全程纯正中文”；英语界面标题/导航/表单大量中文残留 | 与“源内容保留原语言、讲解用生成语言”的要求冲突 |
| 8 | 数据完整性错误：文件缺失仍显示“已保存” | 课程 1 的 4 条生成物全部 `exists=false`，文件页日期 1970/1/1；首页仍写“上次内容已保存”“继续学习” | 用户点进去是空阅读器，信任崩塌 |
| 9 | 学习闭环是空壳 | 练习只支持单选；错题从阅读器加入后 answer/note/page 全空；掌握度只有 boolean；复习计划 0/0 却显示 100% 进度 | 无法形成“练习→错题→复习→掌握”的闭环 |
| 10 | 发布条件不成立 | App 是 ad-hoc 签名，未公证；Windows/官网/GitHub/内测/盲测未做 | 不能对外发布，更不能宣称超过顶级 AI |

### 0.3 一句话判断

> **不是 UI 不漂亮，而是内容不可信、校验不可靠、答案不正确、语言角色不对、学习闭环没打通。先修内容内核，再谈 UI 和发布。**

## 3. 分层详细发现

### 3.1 输入/解析层

**做对的部分**

- 35 页 PDF 能解析出 35 页、15,265 字、1 张图，页账本能工作。
- 上传/删除资料、重复文件处理、UI 上传队列都可用。
- 解析缓存存在，能避免同一路径重复解析。

**问题**

1. **慢且进度不可信**：35 页 150.6s；进度从 8% 长时间不动，ETA 先报 1428.5s，然后直接 100%。用户会以为卡死。
2. **公式文本损坏**：PDF 有文本层，但公式被拆成单字符/乱序（page 2 的导数公式是 `x | x | x ...`），后续模型只能猜。这不是 OCR 问题，是 PDF 公式文本抽取问题。
3. **解析缓存按路径+mtime，不按内容**：同一份 PDF 换个课程/副本就重新解析，35 页又 150s；本次上传副本就重复解析。
4. **“已解析”不可信**：课程详情显示“已解析”只代表文件存在，不代表文本质量/页覆盖合格。
5. **没有解析质量报告**：用户看不到哪些页是文本、哪些是 OCR、哪些是低质/公式损坏。

### 3.2 内容生成层

#### 3.2.1 讲义：从大纲开始就坏了

**实测 1：带老师重点（第 1–4 页，精简）**

- 8.2s 失败。
- 硬违规：
  - `老师必考内容缺失：高阶导数、隐函数求导`
  - `逐句证据不足：0% 段有依据（3 低依据 / 0 无页码）`
- 覆盖率 75%（3/4 页），第 4 页未引用。
- 输出 677 字，两章标题完全相同，都是：
  `## 核心考点：【重点资料·权重3：高数类测试·35页.pdf】`
- 每段结尾固定模板：
  `这句是资料里的直接结论，先记住原句，再结合上下文理解。`
- 正文出现 `P.1`、`P.2`（设计锁定 Brief 明确“正文内不出现 P.x”）。

**实测 2：不带老师重点（第 1–2 页，全量）**

- 8.2s 失败。
- 硬违规：`逐句证据不足：50% 段有依据（1 低依据 / 0 无页码）`
- 覆盖率 100%（2/2 页），但输出 712 字，仍是两章同名、每章一段、模板句。
- 第一章甚至出现空的 `<sup class="src"></sup>（P.1）`。

**根因**

- 大纲走了兜底：`core/generate/outline.py` 的 `fallback_outline()` 用 `_page_head()` 取每页第一行，但没有过滤 `【重点资料·权重3：…】` 这种资料头，于是两章都拿资料头当章名。
- 缓存大纲（`debug/outlines/8d3d6b7bf3ef04cf.json`）明确显示两章同名、每章 2 页。
- 后续章节生成按这个错误大纲走，模型只写一段模板话；`guide_service` 的“卡片/自然成文”没有真正产出。
- 逐句证据用 2-gram，模板句把原文覆盖率稀释到 0%/50%，于是硬杀。**这不是“内容不忠实”，而是校验器把模板句也算进证据分母**，属于误杀；但即使不误杀，677 字也不可能是合格讲义。

**结论**：讲义不是“质量差”，是**管线没有产出讲义**。先修大纲兜底 + 章节生成 + 证据审计，才谈排版。

#### 3.2.2 提取：points 假通过，nouns/questions 真失败

**points（第 1–4 页）**

- 任务 `done`，46.2s，2,016 字。
- `validation.ok=true`、`quality.passed=true`。
- 但：
  - 覆盖率 **0.0**；
  - `pages_cited=0`，`pages_missing=[1,2,3,4]`；
  - 0 条页码；
  - 末尾 4 条只有标题没有内容（“复合函数求导（链式法则）”“多层根式函数的导数计算”“导数化简与通分运算”等）。
- 输出没有 `### 考点：` 结构，而是 `【高阶导数】`。`core/quality/constraints.py` 的 `_check_extract()` 只在 `### 考点：` 块存在时检查出处；没有块就跳过。于是 0% 覆盖也能通过。
- **这是本次最危险的“假通过”**：用户看到“提取完成”，实际上没有任何页码可追溯。

**nouns**

- 108.6s 失败：`名词条目全部缺少出处页码`。
- 28 条 points、0 questions、0 页码。
- 这是一次“正确的失败”：内容确实没有出处；但说明模型不会按 `名词|定义|页码|易混词` 输出。

**questions**

- 44.2s 失败：`资料里有 4 处题号，但输出没有识别到任何题目`。
- 0 题、0 页码。
- 原题提取是四类任务里最刚需的之一；当前直接不可用。

**结论**：points 的“通过”是校验器结构漏洞；nouns/questions 是能力不足。三种提取没有统一的“必须有出处”的硬门禁。

#### 3.2.3 试卷：能生成，但答案不可信

本次为覆盖五种模式，使用 2 题/100 分的小卷（每题 50 分）来降低耗时；这不代表真实卷面，但足以暴露答案审计问题。

**mock（2 题）**

- 20.1s，959 字，2 题，100 分，`validation.ok=true`。
- 第 2 题：
  - 方程 `u² + tan(v) = e^u`，`u(0)=0`，`u'(0)=2`，求 `v'(0)`。
  - 正确：两边对 t 求导 `2u u' + sec²(v) v' = e^u u'`；代入 `0 + 2v' = 2`，所以 `v'=1`。
  - 系统答案：A（-2）；选项是 -2/0/2/4，**没有正确答案 1**。
  - 解析还写“代入得 dv/dt=-2”，代数错误。
- 练习判分：选 A 后显示 **2/2 全对**。学生会被教错，且系统认为这是正确的。
- 第 2 题题干末尾还带上了 `# 答案与解析`，说明题目/答案分区解析有 bug。

**variant（2 题）**

- 24.1s，1,314 字，`validation.ok=true`。
- 第 1 题选项 A 与 C 等价（都是 `sec x tan²x + sec³x`），正确答案不唯一。
- 第 2 题答案 C，但解析自己写：“**无选项匹配该结果**……按命题意图选 C”。题目本身不可做，仍判通过。

**original（2 题）**

- 60.2s，847 字，`validation.ok=true`。
- 输出路径与 variant 相同：`审计课程_20261108_训练试卷_1108_2345.html`。
- variant 随后覆盖了 original；数据库记录 828 的 `train_type` 也变成 `variant`。**original 内容丢失，记录错标。**
- 输出中没有看到“改编自第 X 页第 Y 题”的出处；但校验仍通过，说明 original/variant 的出处硬校验没有真正生效。

**predict / reference**

- predict 54.3s，1,402 字；reference 104.5s，891 字；两题答案人工核对正确。
- 但都没有“预测依据/原卷结构分析/覆盖报告”；`pages_cited=0` 对预测卷可以接受，但对“预测依据”这个要求没有体现。

**共同问题**

- 所有模式都通过结构校验，但没有**答案审计**：没有独立求解、没有选项唯一性检查、没有量纲/边界检查、没有“官方答案冲突”标记。
- 试卷没有卷头时间/考试说明/分值说明的完整结构；只有标题、满分、题型。
- 输出文件按分钟命名，同一分钟多次生成会互相覆盖；DB 记录会指向同一路径。

#### 3.2.4 逻辑分析：空结果

- 4.0s，3 次尝试，`生成结果为空`。
- 不是“内容不好”，是完全没有输出。四类任务缺一类。

### 3.3 阅读器

**能用**

- 打开提取文档，正文显示；搜索“导数”命中 15 处，下一处 2/15；KaTeX 基本渲染；存笔记成功；加入错题成功；Word/PDF 可导出。

**问题**

1. **TOC 空**：提取文档 `toc=[]`，右侧“本章暂无小节”。阅读器没有为无 h2 的提取/试卷提供可用的章节导航。
2. **封面违反设计 Brief**：
   - 显示 `TermFinale · 开发者 Lan`；
   - 显示“本次目标/剩余天数/讲解人设”统计卡；
   - 随机祝福语“把这一章啃下来”；
   - 显示源文件名 `审计课程_20261108_资料提取_1108_2329.html`。
   - 设计锁定 Brief 明确：封面只保留标题/科目，无 App、目标分、人设、天数；正文不出现机器标签/文件名。
3. **公式排版**：嵌套分式（如 `dx/dy = 1/(dy/dx)`）字号过小、分数线粘连；整页是 bullet 墙，行距紧，缺少段落呼吸。
4. **AI 回答**：标 `P.13`、`用户选中页`，但在重排 HTML 里用户无法定位“第 13 页”；回答大量复述正文；KaTeX 文本在 `innerText` 中重复/错位。
5. **错题字段缺失**：阅读器“加入错题”只提交 `{course_id, question}`，没有 answer/解析/页码；错题本无法用于复习。
6. **Word 导出**：`.doc` 不是 `.docx`；提取文档也命名“-讲义.doc”；图片异步转 base64 失败会静默跳过。
7. **PDF 导出**：239KB/53.6s 可用，但后端 fallback URL 用 8900，而服务在 8903；有生成文件时走静态 HTML 才没炸，空课程会失败。
8. **输出位置不一致**：生成 HTML/MD 写到 `~/Desktop`，设置页却显示输出目录是 `~/Library/Application Support/TermFinale/outputs`；用户不知道文件在哪，且桌面被污染。

### 3.4 学习闭环

**练习**

- 只支持单项选择题判分；填空/计算/综合没有判分逻辑。
- 判分只比字母，不做答案解析/二次校验；本次错答案被判对。
- 重复提交会重复写入错题（没有去重）。

**错题本**

- 阅读器加入的错题只有题目，没有答案/解析/页码/错因。
- “记住了/忘了”能推进 stage（1→2），下次日期 11-09→11-10；这是本次少数跑通的功能。
- 没有按知识点/章节的掌握度，只有 `mastered` boolean。
- `practice.html?mistake=17` 深链不打开对应错题，直接忽略参数。

**复习计划**

- 0 到期错题时“今日进度 0/0”，进度条 100%；这不是“完成”，是空数据。
- “预计用时 = 到期错题数 × 2 分钟”，没有依据。
- 没有按剩余天数/目标分/章节权重排计划；只是把 due mistakes 列出来。

**首页/今日**

- “资料覆盖 100%”实际是“1/1 份资料文件存在”，不是页覆盖；这与 SPEC 的“页码覆盖 ≥98%”不是一回事，属于误导。
- 课程 1 的 4 条生成物全部缺失，首页仍写“上次内容已保存”“继续学习”，点进去阅读器提示“旧文件没有 Markdown 源，请重新生成”。
- 课程卡片进度条 `p = generated*12`，是假进度；复习计划 0/0=100%，也是假进度。

### 3.5 约束、个性化与语言

**老师重点**

- 老师重点能被解析成 `must_topics/ban_topics`；本次“高阶导数/隐函数求导必考、参数方程不考”被正确解析。
- 但讲义生成没有覆盖必考内容，硬校验失败；说明“解析”有了，“生成”没跟上。
- 没有在 UI 里展示“哪些必考点已覆盖/未覆盖”的报告。

**人设**

- 人设只在 prompt 里影响语气；UI 下拉直接显示“温柔小姐姐/暴力极客”等，产品感偏弱。
- 结构校验不检查人设是否改变事实；没有抽样对比。

**语言（本次重点纠正项）**

- 生成 prompt 仍是：
  - 英文：`STRICT ENGLISH ONLY ... Do NOT use any Chinese characters.`
  - 中文：`请必须全程使用纯正的中文输出！`
  - 这直接违背“UI 语言/生成语言/源内容语言/译文分层”的要求。
- `core/lang_convert.py` 的 `to_hant`/`to_english` 是整篇转换；`to_english` 只替换少量标签，不能保证源内容保留。
- UI 切换英语后，逐页仍有大量中文：
  - dashboard 294 个中文字符；notes 248；review_plan 202；generate 132；settings 123；course_detail 114；practice 106；materials 90；courses 51。
  - 标题仍是“生成工作台 · TermFinale”“我的课程 · TermFinale”等。
  - 导航混排：`今日 / Course / 练习 / 计划 / Materials / Notes / Settings`。
  - 生成页仍显示“老师重点 / 补充要求”“页码范围”“违规即失败（自动重试 2 次）”。
  - AI 抽屉仍显示“AI 助教”“问这门课”“问资料里的概念…”。
- 没有“界面语言”和“生成语言”的独立设置；语言切换会刷新页面，生成语言靠 `langSelect`，两者概念混在一起。
- **结论**：当前实现是“全文强制单语”，不是“角色内一致、角色间可切换”。这是架构级问题，不是补几个翻译词能解决的。

### 3.6 质量与评测

**已有**

- `validate_output` 四类任务都有代码；175 项测试通过（文档记录）。
- 覆盖率、页码区间、改数/变式出处、预测/模拟禁原页码、自然改写不再 2-gram 硬杀，这些规则有代码。

**实测失效**

- points 0% 覆盖判通过；
- 试卷错答案判通过；
- 讲义 0%/50% 证据误杀；
- 逻辑分析空结果判失败（正确），但没有 fallback；
- 没有答案审计、没有选项唯一性检查、没有量纲/边界检查；
- 没有图片报告落盘/UI；
- 没有覆盖报告页面；首页的“覆盖率”是资料存在率；
- 没有评测集、没有盲测、没有与直接问 AI 的对比。

**结论**：校验器不是“没有”，而是**规则与真实内容脱节**：该拦的没拦（points/试卷），不该杀的杀了（讲义证据），该有报告的地方没有 UI。

### 3.7 UI/UX

- 生成工作台一屏 38 个按钮、18 个输入、15 个下拉；认知负荷过高，像调试后台。
- “权重 1/2/3/4/5”是五个并排小标签，点击热区小，用户不知道是单选还是滑块。
- 设置页直接展示绝对路径、API Key 尾号、模型名；普通学生看不懂。
- 设置页侧栏“练习与错题”是 `<a>` 但没有 `href`，死链。
- 课程卡片有 `data-files` 的“生成物”弹窗代码，但卡片没有 `data-files` 按钮，弹窗不可达。
- 阅读器“编辑”按钮代码存在，但 HTML 没有 `#editBtn`，是死代码。
- 复习计划/首页重复“到期错题”统计；0/0 显示 100%；假进度条。
- 空状态/错误状态不完整；很多页面失败时只 toast，没有可操作的恢复路径。
- 窄窗口/长公式/键盘/对比度未系统验。

### 3.8 系统与性能

- **任务状态在内存**：`JOBS` 是 `server/app.py` 里的全局字典；服务重启/崩溃后任务丢失，无法恢复。代码中没有 resume/checkpoint/crash recovery。
- **取消可用**：API cancel 把任务置 cancelled；UI 有取消按钮。但已生成的部分章节/结果没有断点记录。
- **耗时**：
  - 35 页解析 150.6s；
  - 2 题试卷 20–104s；
  - 10 题试卷 194.6s 只到 59.2%，被取消；
  - 5+2+1+1 试卷 261s 只到 65.8%，被取消；
  - PDF 导出 53.6s。
- **文件覆盖**：试卷按分钟命名，original/variant 同分钟互相覆盖；DB 记录指向同一路径；生成物写到 Desktop，不在 outputs。
- **旧数据**：课程 1 的 4 条生成物全部缺失，文件页显示 1970/1/1，首页仍显示“已保存”。没有迁移/缺失提示。
- **备份**：可用；**恢复**只有 CLI，没有 UI。
- **测试隔离**：我们新建的审计课程默认可见；课程 1 名称“1”也可见。测试数据隔离没有在 UI 层真正成立。

### 3.9 发布

- Mac App 可运行；`codesign` 显示 `Signature=adhoc`，未公证；`spctl` accepted 是因为本机 `security disabled/override`，不是可分发状态。
- Windows/官网/GitHub/10 人内测/盲测均未做。
- 没有发布，不能盲测顶级 AI；之前 P0 95%/97% 不成立，已收回。

## 4. 根因（不是表面 bug）

1. **大纲兜底不可用**：`fallback_outline` 把资料头当章名，章节重复；后面的生成再努力也没用。
2. **生成是“模板填空”而不是“成文”**：prompt 要求教材体，但模型输出固定句；没有 few-shot/示例/多轮修订/章节级质量门槛。
3. **校验器只查结构，不查事实**：points 没有 `### 考点` 就跳过出处；试卷只查题数/分值/答案数量，不查答案对错、选项唯一性。
4. **证据审计用 2-gram**：模板句稀释导致 0%/50% 误杀；自然改写也会被误杀。需要 quote-first + NLI/人工复核。
5. **没有答案审计**：没有独立求解/数值校验/选项一致性；所以错答案能一路通过。
6. **文件/数据模型不稳**：按分钟命名、Desktop 输出、缺失文件仍显示已保存、恢复无 UI。
7. **语言策略旧**：全文强制单语，和“源内容保留原语言、讲解用生成语言”冲突。
8. **UI 用假指标代替真实状态**：生成数当进度、资料存在当覆盖率、0/0 当 100%。
9. **没有 golden set / 人工评分 / 发布门禁**：所以“175 tests pass”不能代表内容可用。

## 7. 重构计划（摘要，详见 `docs/REFACTOR_PLAN_2026-11-08.md`）

**总原则**：先内容内核，后阅读器/学习闭环，最后 UI/发布；不再用“任务成功/测试数/生成数”冒充质量。

1. **Phase 0（1–2 天）**：冻结新功能；清理测试数据；建立 3 份 golden set（文本 PDF、扫描 PDF、英文 PPT）；把本报告的门禁写进 `ULTIMATE_FORM_LOCKED.md`。
2. **Phase 1（1–2 周）**：内容内核。
   - 修 `fallback_outline`：过滤资料头，按真实标题/页码分段；无大纲时失败并提示，不生成假章节。
   - 章节生成：一章一次，source quote → 讲解 → 例题 → 易错 → 小结；禁止模板句；正文不出现 P.x；章末统一出处。
   - 证据：quote-first + 页码 + 句子级匹配；2-gram 只做 warning，不硬杀自然改写。
   - 交付：环烃 1 章样章（自然成文、例题、易错、小结、出处、干净图），人工评分 ≥4/5。
3. **Phase 2（2–3 周）**：四类任务独立管线。
   - 提取：points/nouns/questions 三套 schema；每条必须有页码；原题逐字；含/不含答案。
   - 试卷：blueprint + 题库 + provenance + 答案求解器/校验器 + 选项唯一性 + 重复题/空题；错答案 0 才交付。
   - 分析：七件套 schema；空结果 fail；因果链可回溯。
4. **Phase 3（2 周）**：阅读器 + 学习闭环。
   - TOC 从真实标题；封面只留标题/科目；错题带答案/解析/页码；练习支持多题型；掌握度按知识点；复习计划真实排期。
5. **Phase 4（1–2 周）**：UI/语言/可访问性。
   - UI 语言完整翻译；UI 语言/生成语言/试卷语言分离；窄窗口/长公式/空错加载/死按钮审计。
6. **Phase 5（1–2 周）**：系统可靠性。
   - 任务状态落库；断点续跑；崩溃恢复；1000 页；输出目录/命名/去重。
7. **Phase 6（1–2 周）**：评测与发布。
   - golden set 对比直接问顶级 AI；盲测；Mac 签名/公证；Windows；官网/GitHub；10 人内测。

**工期判断**：一个强工程师全职约 8–12 周；内容质量是瓶颈，不能靠周末补丁。UI 重做必须排在内容通过之后。

## 8. 本次测试的边界

# 底层算法发布标准（Release Standard）

这不是“全部功能完成”的清单，是**底层算法能不能交付**的硬标准。UI 不在这份标准的验收范围内。

## A. 必过项（缺一不可）

| # | 标准 | 判定 |
|---|---|---|
| A1 | 测试套件全绿 | `unittest discover -s tests`，0 fail/error，且 ≥110 项 |
| A2 | 试卷结构 | 题型/题数/分值严格等于设定，合计 100 分 |
| A3 | 试卷答案完整 | **每一道题都有答案**；按大题分节核对；缺一节/缺一题即失败 |
| A4 | 答案分区干净 | 只允许一个「答案与解析」分区；答案后不得再出现第二套题 |
| A5 | 答案内容非空 | 题号后不能只有 `1.`；空答案行即失败 |
| A5b | 选择题字母 | 选择题答案必须是题干里真实存在的 A–D 选项字母；答 E / 答文字即失败 |
| A6 | 老师约束 | 只考/必考/不考/页码进入约束；超范围考点被过滤并计数；未解析项显式列出 |
| A7 | 页码/覆盖账本 | 覆盖率按页计算，不允许 `ok_chunks/chunks` 冒充；缺页必须列出 |
| A8 | 本地安全 | 页面 token + 无 cookie 403 + 跨站 Origin 403；token 重启仍有效 |
| A9 | 数据安全 | 备份可恢复；测试课默认隐藏；reset 不删原资料 |
| A10 | PDF 导出 | 直接打印生成后的单文件 HTML；PDF 里不得出现“正在加载”/`var blob` 脚本 |
| A11 | 逐页账本 | 每页 text/OCR/图片页/占位/未引用可查；不允许只用页头数量冒充内容完整 |
| A12a | ≤150 页 | **精准全量覆盖**：页账本 100%，无未解释占位；图片/OCR 页必须有描述；生成物引用覆盖全部内容页 |
| A12b | >150 页 | **大幅覆盖**：页账本 100%，生成物引用 ≥75% 页；必须明确标“大幅覆盖/概览”，不得冒充逐页精准 |

## B. 已验收的真实样本

- 85 页 PPT：85/85 页；第 74 页 OCR 失败但显式占位。
- 171 页有机化学：**169/171 页引用 = 98.8%**，仅缺 1、2 封面/群号；两个封面页必须在报告中明示。
- 1001 页数学分析：真实概览 **8 章 / 抽样 50 页 / 43.5s**；明确 `overview_sample`，不是逐页。
- 真实试卷：FINAL高数 4/2/2=100 分，8 题 8 答案，`validation.ok=True`。
- 真实 API：4 页 4/4、上传→解析→生成 2/2。

## C. 明确不在这份标准内（不能拿它冒充发布完成）

- 试卷答案的**语义正确性**：现在只保证结构、题题有答案、答案非空；不保证每道计算题算对。
- 1001 页**逐页提取**：长文档产品路径是概览；若要求逐页，需另立预算和验收。
- 171 页两个封面页：不会被当成有考点内容。
- UI 视觉重构、主题/语言：与算法发布标准分开验收。
- Windows/macOS 签名、可分发打包：发布工程，不在算法标准内。

## D. 发布前必须由人确认的三件事

1. 171 页是否接受“内容页 100% + 封面除外”的口径。
2. 1001 页是否接受“概览抽样”作为产品行为，还是必须逐页。
3. 试卷答案是否只要求“题题有答案、结构自洽”，还是要求逐题语义正确。

## 1. 重构目标与非目标

### 1.1 目标

1. **内容可信**：每一章、每一题、每一条考点都能回到资料页；答案经过独立校验；老师必考覆盖、不考不出现。
2. **学习闭环**：阅读→提问→笔记→练习→错题→间隔复习→掌握度→复习计划，真正能跑通。
3. **语言正确**：UI 语言干净；生成语言按用户选择；源内容保留原语言；翻译单独标记。
4. **可发布**：Mac 签名/公证、Windows、官网、内测、盲测、评测集。

### 1.2 非目标（本轮不做）

- 不做社区、移动端、花哨动画、AI 推荐流。
- 不在内容通过前重做全站 UI。
- 不用“175 项测试通过”“160/160 任务成功”作为内容质量证明。
- 不承诺零错误；只承诺错误可发现、可追溯、可修正。

## 2. 当前架构的问题（为什么必须重构而不是打补丁）

| 层 | 现状 | 问题 |
|---|---|---|
| 解析 | PDF/PPTX/DOCX/OCR 都有入口 | 35 页 150s；公式文本被拆散；缓存按路径不按内容；无解析质量报告 |
| 大纲 | AI 大纲 + `fallback_outline` | 兜底把资料头当章名，两章同名；没有“无大纲就失败”的勇气 |
| 章节生成 | 一个 prompt 生成一段/一章 | 模板句；677 字；没有章节级证据/例题/小结门禁 |
| 证据 | 2-gram 覆盖 | 模板句稀释导致 0%/50% 误杀；自然改写也会误杀 |
| 提取 | 三个类型共用一个提取器 | points 没有 `### 考点` 就跳过出处；nouns/questions 失败 |
| 试卷 | 一个 exam prompt | 答案算错仍通过；选项重复；无 provenance；文件覆盖 |
| 分析 | 一个 prompt | 空结果 |
| 阅读器 | 渲染 HTML + 搜索/问答 | TOC 空；封面泄露开发者/文件名；错题字段空；回答页码不可定位 |
| 学习 | mistake + stage | 只支持单选判分；无知识点掌握度；计划是静态统计 |
| 校验 | 规则散落在 constraints/quality | 该拦的没拦，不该杀的杀了；没有答案审计 |
| 语言 | 全文强制单语 | 与源内容保留冲突；UI 翻译不完整 |
| 系统 | 内存 JOBS + Desktop 输出 | 重启丢任务；文件覆盖/缺失；无恢复 UI |

**结论**：不是某个函数写错，而是**内容生产没有“证据优先”的架构**。必须把“生成”改成“先取证据、再写讲解、再校验”的管线。

## 3. 目标架构

```
资料
  ↓
① 页账本 / 解析质量
  ↓
② 课程大纲（真实章节，失败即失败）
  ↓
③ 章节级内容生成（source quote → 讲解 → 例题 → 易错 → 小结）
  ↓
④ 任务级结构化输出（讲义/提取/试卷/分析）
  ↓
⑤ 质量门禁（覆盖/出处/老师/答案/图片/语言）
  ↓
⑥ 质量报告 + 阅读器 + 学习闭环
  ↓
⑦ 评测集 / 盲测 / 发布
```

### 3.1 模块划分

| 模块 | 职责 | 关键输出 |
|---|---|---|
| `ingest` | 解析、OCR、页账本、公式修复、解析质量 | `PageLedger`：每页文本/图片/OCR/质量/缺失原因 |
| `curriculum` | 大纲生成、标题清洗、章节页码、失败处理 | `Outline`：章节标题、页码、重要度；禁止资料头当标题 |
| `authoring` | 章节成文、例题、易错、小结、出处 | `ChapterDraft`：段落、引用、页码、例子、标记 |
| `extract` | points/nouns/questions 三套 schema | `PointsDoc` / `NounsDoc` / `QuestionsDoc` |
| `exam` | blueprint、题库、provenance、答案求解/校验 | `Paper` + `AnswerAudit` |
| `analysis` | 七件套结构、因果链、推断标记 | `AnalysisDoc` |
| `quality` | 覆盖、出处、老师、答案、图片、语言、结构 | `QualityReport`（可落盘/可展示） |
| `reader` | 渲染、TOC、搜索、问答、笔记、导出 | 阅读器数据 |
| `learning` | 练习、判分、错题、间隔复习、掌握度、计划 | 学习数据 |
| `platform` | 任务、缓存、断点、备份/恢复、测试隔离 | 可靠任务 |
| `i18n` | UI/生成/源内容/译文四角色 | 语言策略 |

### 3.2 数据契约（先定 schema，再写 prompt）

- `PageLedger`：`page_no, text, text_quality, images, ocr_used, formula_damage, missing_reason`
- `Outline`：`chapters[{title, pages, importance, must_know}]`；`source` 只能是 `ai/fallback/manual`，且 fallback 必须标题有效。
- `ChapterDraft`：`title, sections[{heading, paragraphs, quotes[{text,page}], example, pitfalls, summary}], sources[]`
- `PointsDoc`：`items[{point, keywords, pitfalls, page}]`
- `NounsDoc`：`items[{term, definition, page, confused_with}]`
- `QuestionsDoc`：`items[{no, stem, options, answer, analysis, source_page, source_no, original_language}]`
- `Paper`：`meta, sections[{name,count,points}], questions[{no,type,stem,options,points,answer,analysis,source}], answers[]`
- `AnswerAudit`：`{method, independent_answer, agrees, conflict, confidence, manual_required}`
- `AnalysisDoc`：`{one_line, concepts[], causal_chain[], exam_map[], confusions[], order[], citations[], inferences[]}`
- `QualityReport`：`{hard_issues[], warnings[], coverage, citations, teacher, answers, images, language, evidence}`
- `LanguagePolicy`：`{ui_lang, gen_lang, source_lang, translation_mode}`

**原则**：结构先定，模型输出 JSON/受控 Markdown；不要让模型自由发挥后再用正则猜结构。

## 4. 分阶段计划

### Phase 0：冻结与基线（1–2 天）

**目标**：停止“功能越多越好”，把标准焊死。

- 冻结新功能；只修 P0。
- 清理/隐藏测试数据：审计课程 `is_test=true` 或删除；课程 1 的缺失生成物标记“文件缺失”，首页不再写“已保存”。
- 建立 golden set：
  1. 35 页文本 PDF（本次高数）；
  2. 扫描/图片 PDF（OCR 路径）；
  3. 66 页英文 PPT（语言角色）。
- 把 `docs/ULTIMATE_FORM_LOCKED.md` 作为唯一验收标准；旧 `ULTIMATE_FORM.md`/`SPEC_GUIDE.md` 的“全文一致”语言条款标记为待替换。
- 产出：一页“当前 P0 清单 + 验收门禁”，不再报百分比。

**验收**：所有后续任务必须引用 locked 标准；没有“任务成功=内容通过”。

### Phase 1：内容内核（1–2 周）

**目标**：先让“一章”真正能读。

1. **修大纲**
   - `_page_head` 过滤资料头/页码头/图片标签；
   - `fallback_outline` 按真实标题/页码分段；标题无效就 `RuntimeError`，不生成假章节；
   - 大纲缓存按内容 hash；测试数据 namespace。
2. **章节生成**
   - 一章一次调用；输入：该章页码原文 + 必考/不考 + 前后章关系；
   - 输出：自然成文，至少包含考点、概念/公式、推导、例题、易错、小结；
   - 禁止模板句；正文不出现 P.x；章末统一“本章出处”；
   - 例题必须有教学价值；资料没有就标【延伸】，不硬编。
3. **证据**
   - 生成时要求“引用原句 + 页码”；校验时先匹配引用，再判断讲解；
   - 2-gram 只做 warning；自然改写走语义/人工抽检；
   - 事实性断言无依据 → 硬失败；解释/延伸 → 警告。
4. **交付**
   - 环烃 1 章样章：自然成文、例题、易错、小结、出处、干净图；
   - 人工评分 ≥4/5（学生能读懂、记得住、能做课后题）；
   - 覆盖率 100%（该章页范围），缺失页列出。

**验收**：不再出现 677 字模板讲义；不再两章同名；不再用 P.x 塞正文。

### Phase 2：四类任务独立管线（2–3 周）

#### 2.1 提取

- 三套独立 schema/prompt/validator：
  - points：每条 `point + page`；没有页码 = 硬失败；覆盖 100%。
  - nouns：`term | definition | page | confused_with`；无定义标“资料未给定义”；无页码硬失败。
  - questions：原题逐字、原题号、选项、答案/解析、page/source_no；没答案写“原卷未给答案”；含/不含答案两模式。
- 覆盖检查不再依赖 `### 考点`；按条目/页账本检查。
- 交付：三类各一份真实样例，0 条无出处，0 条改写。

#### 2.2 试卷

- `blueprint`：题型/题量/分值/难度先定，再出题。
- 题库/provenance：original/variant 必须“改编自第 X 页第 Y 题”；无 provenance 硬失败。
- 答案审计：
  - 独立第二遍求解；
  - 数值题用 SymPy/单位检查；化学用 RDKit/价态；文本题用引用+人工；
  - 选项唯一性检查；答案必须在选项内；
  - 冲突标“争议”，不交付。
- 去重/空题/分值合计/卷头完整。
- 交付：mock/predict/original/variant/reference 各一份；错答案 0；重复题 0；空题 0。

#### 2.3 逻辑分析

- 七件套 schema：一句话主线、概念层级、因果链、考点题型映射、易混对比、学习顺序、页码出处。
- 事实 vs【推断】分开；空结果硬失败；每条因果链必须能回溯。
- 交付：一份真实样例；3 句话能复述主线。

**验收**：四类任务各一份真实样例，全部过 locked 门禁；不再用“任务完成”代替“内容通过”。

### Phase 3：阅读器 + 学习闭环（2 周）

**阅读器**

- TOC 从真实标题（h2/h3）生成；提取/试卷也要有可用的“题目/考点”导航。
- 封面只留标题/科目；移除开发者、随机祝福、目标/天数/人设统计、源文件名。
- 公式排版：嵌套分式字号、行距、长公式换行；搜索高亮对比度。
- AI 问答：回答分层（结论/步骤/出处）；页码可点击定位；不重复正文；回答 Markdown 正确渲染。
- 错题：加入时带题目、答案、解析、页码、课程、错因。
- Word 导出 `.docx`（或明确 `.doc`），文件名按文档类型；PDF 输出目录/端口修正。

**学习闭环**

- 练习支持选择/填空/计算/综合；判分用答案审计。
- 错题本字段完整；重复提交去重；按知识点/章节统计掌握度。
- 复习计划按剩余天数/目标分/章节权重排期；今日进度真实（完成数/计划数）。
- 首页“资料覆盖”改成“页覆盖”，文件缺失显示“缺失/需重生成”，不再写“已保存”。

**验收**：练习→错题→复习→掌握度全链路可走；错题能回到讲义对应页；进度不是假条。

### Phase 4：UI / 语言 / 可访问性（1–2 周）

- UI 语言完整字典：标题、导航、按钮、表单、空/错/加载、校验提示、导出对话框。
- 分离：界面语言、生成语言、试卷语言；切换 UI 不追溯改生成物。
- 语言角色：
  - 源内容（原文/原题/术语/例句）保留原语言；
  - 讲解/解析/总结用生成语言；
  - 翻译单独标“参考译文”，不覆盖原文；
  - 校验器检查角色，不把“混排”本身当违规。
- 窄窗口/长公式/键盘/对比度/空错加载/死按钮审计。
- 移除死链：设置页“练习与错题”、课程卡“生成物”弹窗、`practice.html?mistake=`。

**验收**：英语界面除源内容外 0 中文残留；0 死按钮；窄窗口无溢出。

### Phase 5：系统可靠性（1–2 周）

- 任务状态落库（SQLite），重启可恢复；每章/每块 checkpoint。
- 断点续跑：取消/崩溃后从最后完成块继续；幂等输出。
- 输出命名带秒/任务 id，避免同分钟覆盖；统一到 `outputs/`。
- 解析缓存按内容 hash；测试数据 namespace；清理策略。
- 1000 页长文档：分块、并发、限流、进度/ETA 基于完成块，不造假。
- 备份/恢复 UI；恢复前自动备份；坏备份拒绝。
- **验收**：kill 服务后重启能续；1000 页任务完成；无数据丢失/覆盖。

### Phase 6：评测与发布（1–2 周）

- golden set 跑四类任务；人工评分 + 与“直接问顶级 AI + 强提示词”对比。
- 指标：覆盖率、出处准确率、答案正确率、可做题率、耗时、成本、语言保真、图片质量。
- 盲测：至少 10 名学生；对比直接 AI。
- Mac 签名/公证；Windows 安装包/实体机；官网；GitHub AGPL-3.0；10 人内测。
- **验收**：内容、UI、数据、答案、安装包全过才叫发布。

## 6. 质量门禁（写进 CI/发布）

### 6.1 硬门禁（不过即失败）

- 覆盖：≤150 页 ≥98%，缺失页逐页列出；>150 页概览明确。
- 出处：重要结论 100% 页码；原题 100% 原样；无编页码/定理/题目/答案。
- 老师：必考 100% 覆盖；不考 0 命中。
- 答案：独立审计；错答案 0；选项唯一；答案在选项内；量纲/边界通过。
- 结构：0 空章、0 重复章、0 只有标题；0 重复题、0 空题、0 无答案。
- 图片：0 PPT 截图/色块/logo 冒充；图源/使用/丢弃报告完整；结构图清晰。
- 语言：UI 0 混排；源内容 0 擅自翻译；译文 100% 标记；生成语言一致。
- 公式：0 裸 LaTeX；0 渲染错误。
- 系统：任务可取消/可恢复；输出不覆盖；用户资料不丢。

### 6.2 软门禁（警告 + 人工复核）

- 自然改写语义证据；
- 例题教学价值；
- 小结质量；
- 人设语气；
- UI 美观/可访问性。

### 6.3 发布门禁

- 内容：四类任务各 1 份真实样例，人工评分 ≥4/5。
- 答案：错答案 0；争议已标。
- UI：英语 0 残留；0 死按钮；空/错/加载完整。
- 系统：断点续跑/1000 页通过。
- 安装包：Mac 签名/公证；Windows 实体机。
- 评测：盲测完成；与直接 AI 对比有数据。
- 没有全过，不叫发布。

## 7. 语言策略（必须改）

### 7.1 四角色

1. **UI 语言**：按钮/菜单/标题/空错加载/提示/对话框；切换后完整、干净、不并列双语。
2. **生成语言**：讲义正文、过渡、总结、易错、答案解析、分析说明；按用户选择，全文一致。
3. **源内容语言**：原文引用、原题、术语、例句、标题、代码、公式；保留原语言，不擅自翻译/改写。
4. **译文**：需要时单独标“参考译文”，不覆盖原文；原题提取的译文只能放旁边，不能进题干。

### 7.2 示例

- 英语课资料 + 中文生成：原文/原题/术语英文，讲解中文；术语首次 `source term（中文）`，之后按课程/考试习惯。
- 中文资料 + 英文生成：原文/原题中文，讲解英文；术语保留中文，可加英文注释。
- 繁體原文 + 简体生成：原文繁體，讲解简体；转写标明。
- 试卷：题干语言跟课程/原题；解析跟生成语言；整卷换语言需单独“试卷语言”。

### 7.3 校验

- 不再把“中英混排”本身当违规；
- 检查：UI 混排、生成语言不一致、原文被翻译/改写、原题被改动、译文未标、术语被替换、含答案模式泄题。

---

## 8. 数据与测试隔离

- 测试课程 `is_test=true`，默认不出现在 `/api/courses`、首页、练习、笔记、错题。
- 解析/大纲缓存 namespace：`test/` vs `prod/`；内容 hash 而非路径。
- 审计产物放 `docs/evidence/` 或临时目录，不写 Desktop。
- 删除课程/清空数据前自动备份；恢复 UI 可用；坏备份拒绝。
- 不重置用户数据；不删原资料；生成物缺失要显示“缺失/需重生成”，不能显示“已保存”。

---

## 9. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 内容质量提升慢 | 模型一次写不好一章 | 章节级多轮修订 + 人工评审 + 小步交付 |
| 答案审计难 | 数学/物理/化学各有求解器 | 先覆盖数值/选择/填空；文本题人工复核 |
| 成本/时间 | 35 页 150s；试卷 20–100s | 分块缓存、并发、只生成必要页；不重复解析 |
| UI 返工 | 现在 UI 建立在假数据上 | 先修数据契约，再改 UI；不做大重写 |
| 发布压力 | 用户想尽快看到 | 先做 1 章样章 + 1 套四类样例，再谈发布 |
| 旧文档冲突 | 旧 SPEC 说“全文一致” | 以 locked 标准为准；Phase 0 替换旧条款 |

---

## 10. 立即可做的 5 件事（不等大重构）

1. **把审计课程设为 test 或删除**；清掉 Desktop 测试输出；保留 `docs/evidence/`。
2. **修 `fallback_outline` 资料头过滤**；没有有效标题就失败，不生成假章节。
3. **修提取 points 的出处门禁**：没有 `### 考点` 也要按条目/页账本检查；0 页码硬失败。
4. **给试卷加答案审计最小版**：选项唯一性 + 答案必须在选项内 + 独立重算数值；不过不交付。
5. **把首页“资料覆盖”改成“页覆盖”**；文件缺失显示“需重生成”，不再写“已保存”。

## 11. 一句话

> **先让一章可信，再让四类任务可信，再让学习闭环可信，最后才让 UI 和发布可信。**
> 顺序反了，就会继续得到“按钮很多、内容不能用”的产品。

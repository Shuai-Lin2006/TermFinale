# TermFinale 发布计划（Beta）

> 目标：让前 10 位内测用户能下载、安装、用你的 Key 跑通一次，并能安全地关停和更新。
> 仓库现状：`Shuai-Lin2006/TermFinale` 已存在且公开，但目前只有 README，没有 License、Release、Pages。

---

## 一、发布顺序（不要跳步）

| 顺序 | 做什么 | 为什么是这个顺序 |
|---|---|---|
| 1 | 整理代码、合并基线提交并推送 GitHub | 网页和 Release 都要指向仓库；先有源码才能发 AGPL |
| 2 | 在 Mac 上打包 `.app`，本机完整跑一遍 | 先确认包能启动、能生成，再谈分发 |
| 3 | 在 Windows 上打包 `.exe`，同样跑一遍 | Windows 需要单独构建和测试 |
| 4 | 建 GitHub Release（v0.4.0-beta），上传 Mac/Win 安装包 | 下载页的按钮最终指向 Release 资产 |
| 5 | 做下载页（GitHub Pages），按钮指向 Release | 先有稳定下载地址，网页才不会挂空链接 |
| 6 | 找 1–2 台干净电脑试装、试下载 | 排除“你机器上能跑、别人装不上” |
| 7 | 发链接 + 发 Key + 收反馈 | 最后才是对外 |

**不要先做网页**：网页上的下载按钮需要稳定的 Release 地址，否则以后每次发版都要改网页。

## 二、10 个内测用户的 Key 方案

### 推荐做法：一人一套 Key，而不是所有人共用一个

- 每个用户、每个平台单独建 Key（最多 10×3 = 30 个）
- Key 命名：`beta-01-deepseek`、`beta-01-dashscope`、`beta-01-kimi`
- 单独发给本人，不放群公告、不进仓库
- 到期日统一，比如 14 天后，逐个删除/禁用

原因：

- 谁超量、谁泄露，一眼能看出来
- 出问题只停一个人，不用全员换 Key
- 共用一个 Key 时，一个人被滥用，你只能整个停掉

### 平台限额能力（以各平台控制台为准）

- **DeepSeek**：可创建多个 API Key；账户级余额和用量告警，通常没有“每个 Key 单独限额”，需要你每天看用量
- **阿里云百炼**：可创建多个 API Key；有业务空间/额度体系，适合按用户隔离
- **Kimi**：可创建多个 Key；具体限额以控制台为准

如果某个平台不支持单 Key 限额，就用“**每天人工看一次用量 + 超额立刻删 Key**”兜底，不要指望平台帮你兜。

### 风险控制清单

- 只发给实名的前 10 位用户，说明“仅限本人测试，禁止转发”
- 约定到期日，到期前一天提醒，到期当天删除
- 不把 Key 写进安装包、README、网页、GitHub Issue
- 用户把 Key 填进软件后，只存在他本机 `.env`
- 发现异常用量：先删该用户 Key，再排查

## 三、余额与每天限额（估算，按实际模型价格为准）

### 单次成本参考

实测：一份 **12 页**讲义生成用了 **41,808 tokens**（7 次调用）。
按常见商用模型每百万 tokens 几元到十几元估算：

- 10 页左右一章：约 **4–8 万 tokens**，成本大致 **几毛钱**
- 一整本 1000 页教材（约 100 章）：约 **400 万 tokens**，成本大致 **十几到几十元**
- 加上复核、补讲、出题，成本会再高一些

> 所以“几块钱能用很久”只对**少量章节**成立；整本教材不便宜。对外文案建议改成：
> “一章通常几毛钱，整本教材十几到几十元，具体取决于页数和模型。”

### 建议预留（10 人、2 周、每人每天一章以内）

| 平台 | 建议余额 | 说明 |
|---|---|---|
| DeepSeek | **¥100–200** | 主力生成，按 10 人 × 10 章 × 几毛估算 |
| 阿里云百炼 | **¥50–100** | 复核、图片理解；不开也不影响主流程 |
| Kimi | **¥30–50** | 备用复核，用量小 |

### 每天限额建议

- 每人每天：**1–2 章**（约 10 万–20 万 tokens），够体验，不会烧穿
- 平台如果支持每日额度：DeepSeek 每 Key 约 **20 万 tokens/天**；百炼每 Key **30–50 次调用/天**；Kimi **20–30 次/天**
- 不支持的话：每天固定时间看一次用量，超过预期就停该用户

## 四、并发会不会崩？

- 软件是**本地应用**，用户机器直接调用模型平台；你没有中间服务器，所以**你的软件不会被并发压垮**
- 真正的瓶颈是**模型平台的限流**：共用 Key 时，10 人同时生成可能触发 429（请求过多）
- 一人一 Key 后，限流只影响个人，不会互相拖累
- 下载页是 GitHub Pages 静态页，10 人访问没有压力

## 五、能不能一键关停？

**没有远程开关**。当前版本没有“服务器指令让所有客户端停止”的能力，这是有意的（隐私和信任）。

实际可用的关停方式：

1. **删 Key**：最有效。删掉后，所有人无法再生成/问答（已下载的讲义仍能看）
2. **发公告**：在群里/网页说明暂停原因
3. 想彻底禁止使用：只能让用户卸载，或以后加“启动时检查公告”的机制（需要联网，且会被绕过）

建议：内测阶段就用“删 Key”作为关停开关，简单可靠。

## 六、以后怎么更新？用户怎么拿到新版本？

当前**没有自动更新**，流程是手动的：

1. 改代码，改版本号
2. Mac / Windows 各自重新打包
3. GitHub 建一个新 Release（例如 `v0.4.1`），上传新安装包
4. 下载页如果用 `releases/latest/download/...` 链接，**不用改网页**，按钮自动指向最新版
5. 在群里/更新日志里说明改了什么

用户操作：

- 下载新安装包，覆盖安装
- 课程、讲义、笔记在用户数据目录，**覆盖安装不会丢**
- 不需要用户重新填 Key（Key 在 `.env` 里）

如果以后想要“打开软件提示有新版本”，可以加一个只读的版本清单（GitHub Pages 上一个 JSON），但不要做强制更新。

## 七、Mac / Windows 打包的现实问题

### macOS

- 未签名/未公证的 App，用户第一次打开会被 Gatekeeper 拦
- 解决：右键 → 打开；或在系统设置里允许
- 正式方案：Apple Developer 账号（$99/年）+ 签名 + 公证；Beta 可以先不做，但在下载页写清楚

### Windows

- PyInstaller 打的 exe 没有代码签名，SmartScreen 会提示“未知发布者”
- 解决：下载页说明“更多信息 → 仍要运行”；正式方案是买代码签名证书
- 需要在一台干净的 Windows 上验证：能启动、能解析 PDF、能生成

## 八、下载页放哪里？

- **GitHub Pages**（仓库 Settings → Pages，指向 `docs/` 或 `gh-pages` 分支）最简单、免费
- 国内访问 GitHub Pages 可能慢或被墙，这是现实问题
- 备用：Cloudflare Pages / Vercel 静态托管，绑定自己的域名；下载文件仍放 GitHub Release
- 页面必备：Mac 下载、Windows 下载、版本号、系统要求、License（AGPL）与源码链接、内测说明

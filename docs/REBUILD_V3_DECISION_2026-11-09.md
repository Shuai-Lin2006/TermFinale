# TermFinale 重构判断与 v3 落地（2026-11-09）

> 这份文件回答三件事：
> 1. 为什么过去反复修还是修不好；
> 2. 这次我实际跑出了什么问题；
> 3. 最快能发布的路径是什么，以及 v3 现在到底做了什么、没做什么。

---

## 1. 一句话判断

**过去不是“功能不够”，而是“产品展示的和真正可信的不是同一份数据”。**

旧 App（8903）有漂亮的壳，但首页/课程/练习/阅读器读的是旧 DB + 旧文件 + 内存任务；
v2（8905）有可信的页账本/质量报告/电路样章，却只是一个独立讲义库；
两边没有切换，所以每次修 v2，用户看到的旧 App 还是旧的；每次修旧 App，又绕开 v2 的门禁。
**修的不是同一个产品。**

---

## 2. 我实际跑出来的证据（2026-11-09）

### 2.1 旧 App（127.0.0.1:8903）

- 课程 1：4 条生成物全部 `exists=false`（id 1/2/178/179），首页仍写“上次内容已保存”“4 份生成物”。
- 课程详情用 `?course=1` 正常；用 `?course_id=1` 显示“缺少课程编号”（路由参数不一致）。
- 阅读器 `reader.html?course=1` 显示“还没有可读的内容 / 旧文件没有 Markdown 源，请重新生成”。
- 首页“资料覆盖 100%”实际是“1/1 份资料文件存在”，不是页覆盖。
- 练习/复习为空；课程详情能正确显示“文件缺失/需重生成”，但首页没同步——**同一产品两套真相**。
- 旧生成工作台仍暴露四类任务入口；这些入口背后的旧管线就是 2026-11-08 审计里 677 字模板、points 0% 假通过、mock 错答案判对的那套。

### 2.2 v2 讲义库（127.0.0.1:8905）

- 7 份 artifact；电路全章 80 covered + 5 目录 overview，0 partial / 0 missing；24 页 PDF，14 图，9 书签/19 链接。
- 但 v2 只是“讲义库 + 阅读器”，没有课程/首页/学习闭环；用户不会把它当产品入口。
- v2 的电路样章质量报告是真的；但它和旧 App 的课程/练习/错题完全不连通。

### 2.3 根因（不是某个函数写错）

1. **两套产品、两套真相**：旧 App 的 DB/JOBS/文件 vs v2 的 artifact/manifest/coverage_audit；UI 读旧，质量在 v2。
2. **用“任务完成”代替“内容通过”**：旧 UI 的绿色/进度来自 job 状态和生成数，不读 Gate/审计。
3. **自由 Markdown + 事后正则**：生成时没有结构化证据，校验只能猜；该拦的没拦（points 0%、错答案），不该杀的杀了（自然改写被 2-gram 误杀）。
4. **补丁文化**：`gapfix-*`、section 级 SourceRef、整页截图凑图；每补一次就多一套矛盾（旧版 8V/9mA/RL 例题数值全错，3.5 还编了资料里没有的微分/积分）。
5. **没有 golden set / 人工复核**：所有“通过”都是同一模型/同一套关键词判定；76 项测试全绿，但页面链接和例题数值仍然错。
6. **UI 建在假指标上**：资料存在=覆盖率、生成数=进度、0/0=100%；换 UI 只会把假数字做得更漂亮。
7. **四类任务共用一个旧入口**：讲义/提取/试卷/分析互相污染；一条管线坏，四个按钮都不可信。

## 3. 这次的决定

### 3.1 不再往旧 App 的内容管线打补丁

- 旧 App 保留可启动/可回滚，但**冻结为 legacy**：首页/生成页加“旧版工作台已冻结”提示。
- 旧四类生成不再作为交付；页面只作为历史入口，不参与 v3 质量口径。
- 不再用旧 DB 的生成物/进度/覆盖率作为产品指标。

### 3.2 v3 学习台成为唯一产品入口

新 App：`tfv2/api/product_app.py` + `web_v2/`，默认 `127.0.0.1:8907`，桌面 `desktop.py` 已改为打开它。

它只做三件事，但每件都读真数据：

1. **讲义库 / 质量报告**：扫描 `docs/evidence/*` 与 `data/artifacts/*` 的 `manifest.json`；显示 Gate、内容/PDF/语言体检、语义审计 covered/partial/missing/visual/overview、图源、缺失页。
2. **阅读 / 笔记 / AI**：阅读器直接吃 v2 `lecture.html`（KaTeX/TOC/搜索/编辑/导出/AI），v3 外边加返回/练习/PDF；选中文本“存笔记”写入本地 SQLite。
3. **练习 / 错题 / 复习 / 掌握度**：从当前小节出单选题（服务端判分、答案不下发），错题自动入本，按 1/2/4/7 天复习，掌握度按真实 attempts 算，0 次显示“—”，不显示 100%。

状态口径：

- **可读** = Gate + 内容/PDF/语言体检 + 语义审计 0 partial / 0 missing / 0 visual / 0 empty。
- **待复核** = Gate 过了，但没有语义审计，或有 visual/empty/partial/missing。
- **未通过** = 任一硬门禁失败。
- 没有 coverage_audit 的产物**永远不标可读**。

### 3.3 生成：只保留“实验管线”，不冒充教材级

v3 新增“新建讲义”（PDF/PPTX）：

- 页账本 → 每 5 页一段 → 逐段结构化成文（每段必须引用该段每一页）→ Gate → PDF。
- 试卷/答题纸会被拒绝；不做教材大纲、不自动配图；生成后**没有语义审计**，所以最多“待复核”。
- 生成失败直接报错，不写“已完成”。
- 实测：6 页医学 PDF → 2 段、Gate 通过、5 页讲义、状态“待复核”；1 页 PDF → 4 页讲义、Gate 通过、状态“待复核”。测试产物已清理。
- 这条管线不是最终形态；它证明“输入→页账本→结构化内容→Gate”能跑，但大纲/配图还要继续做。四类任务已另起 typed 管线（见 3.4），不混在讲义生成里。

## 4. 为什么不是“全部重写”

- 旧 App 的视觉壳是可用的，但它的数据契约是错的；重写视觉壳不会修数据。
- v3 没有从零造渲染器/解析器，而是复用 v2 已验证的页账本、Gate、PDF、阅读器；重写这些会丢掉已经过的电路样章和 76 项测试。
- 真正的“重构”发生在**数据契约和入口**：旧 UI 冻结，v3 只读 artifact+QualityReport；学习和讲义共用同一份 artifact。
### 3.4 四类任务：typed schema + 确定性门禁
- 提取考点 / 名词 / 原题：每条必须带页，页码必须在本节页范围内；选项必须 4 个且唯一，答案必须在选项内；原题模式要求题干能在资料页文本中找到，找不到就拒绝。
- 试卷：原题/变式/模拟三种模式；选项唯一、答案在选项内、页有效；**第二遍独立解题**做答案审计，冲突就标 rejected，不静默改答案。
- 逻辑分析：一句话主线 + 概念层级 + 因果链 + 考点映射 + 易混 + 顺序 + 出处；空结果/少于阈值/引用页码无效即拒绝。
- 结果存本机 SQLite `documents`，UI 状态只有 `validated`/`rejected`；UI 写“机器门禁通过”，不写“内容正确”。人工复核/golden set 仍未做。

## 6. 还没做 / 发布阻塞

1. **AI 只能问答/出题/计划/提炼，不能直接写回讲义/生成整份资料并撤销**：AI 写操作规划器、工具调用、预览/撤销未做。
2. **四类任务已有机器门禁，但没有人工复核/golden set**：原题逐字检查用的是讲义文本，可能误杀；答案审计是模型第二遍，不是数值求解器；分析七件套有页码门禁，不是学科专家判断。旧 App 入口仍冻结。
3. **自动配图**：v3 生成已优先用资料大纲（每段最多 8 页，无大纲回退按页），并自动匹配资料页图（每节最多 3 张，图注写明“自动匹配，需人工复核”）。这不是语义配图；发布前仍要逐图核对应关系。
4. **语义审计没有自动化到 v3 UI**：v3 读 coverage_audit.json，但不负责生成它；生成物因此停在“待复核”。
5. **人工复核 / golden set 未做**：电路样章的 0 partial 是模型审计，不是学科专家签字。
6. **Word 原生 .docx 已接讲义导出，但未在 Microsoft Word 客户端验收**：`/artifact/{id}/lecture.docx` 已能生成 144 段 / 14 图 / 0 原始 LaTeX 的 docx；四类任务没有 Word 导出；LibreOffice 本机缺 CJK 字体，视觉验收不能作为 Word 版式通过。
7. **打包/签名/公证/Windows/官网/内测/盲测**未做；`desktop.py` 只验证了服务入口，未做安装包。
8. **旧 App 数据迁移**：旧课程/资料/生成物仍在旧 DB；v3 只读 v2 artifact，未做迁移。

## 7. 最快发布路径（建议）

**先发“可读讲义 + 学习闭环 + 四类任务工作台”的单产品；四类任务可以进首发，但必须带“机器门禁通过 ≠ 人工验收”的标注。**

- 第 1 周：v3 入口替换旧 App；把已审核的讲义迁进 `data/artifacts`；清理测试数据；Mac 打包/签名/公证。
- 第 2 周：补 1–2 份真实课程的逐章精写；每份过 Gate + 语义审计 + 人工抽检；练习/错题/复习跑 10 个学生。
- 第 3 周：四类任务做人工抽检 + golden set；重点查原题逐字、答案审计冲突、分析因果链；Word 只覆盖讲义，任务导出另做。
- 第 4 周：Windows/官网/内测/盲测；没有全过，不叫发布。

**判断**：这比“继续在旧 App 上把四个按钮修好”快，因为旧 App 的四类任务没有可信数据契约；也比“从零重写九层”快，因为 v2 的页账本/Gate/PDF/阅读器已经过电路样章。

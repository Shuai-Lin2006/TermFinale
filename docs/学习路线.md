# TermFinale 长期学习路线（技术栈 + 知识框架 + 怎么学）

> 目标不是背代码，而是建立一张能自我扩展的知识网：看到任何一层，知道它解决什么问题、边界在哪、怎么验证。
> 建议周期：6 个月，每周 8–10 小时；不要按“7 天速成”学。

## 0. 先建立能力地图

把这个项目拆成 4 层，每层都能独立讲：

1. **基础层**：操作系统、文件/编码、HTTP、Git、Python
2. **应用层**：FastAPI、SQLite、前端、桌面壳
3. **领域层**：PDF/PPTX/DOCX、OCR、LLM、质量评估
4. **交付层**：测试、CI、打包、签名、发布、许可

面试失败通常不是“不会某个库”，而是**层与层之间说不清**：比如 PDF 解析结果怎么变成页账本、页账本怎么约束模型、门禁怎么阻止坏结果。

## 2. 十二个知识模块

每个模块按“概念 → 项目锚点 → 练习 → 掌握标准”学。

### M1 计算机与 Python 基础

**概念**：进程/线程、内存、文件描述符、编码（UTF-8/GBK）、路径、环境变量、虚拟环境、包管理、异常栈。
**项目锚点**：`desktop.py` 启动、`launcher.py` 单实例、`core/logger.py`。
**练习**：写一个脚本，启动子进程、捕获输出、处理端口占用和编码错误。
**掌握标准**：能解释为什么 Windows 上 `sys.stdout` 可能是 None、为什么要 `encoding="utf-8"`。

### M2 HTTP 与 FastAPI

**概念**：请求/响应、方法、状态码、Header、Cookie、CORS、JSON、超时、轮询、幂等。
**项目锚点**：`tfv2/api/product_app.py` 的路由、任务创建/查询/取消。
**练习**：用 curl 完成上传→建任务→轮询→下载全流程；画时序图。
**掌握标准**：能解释为什么生成用“任务 + 轮询”而不是一个长 HTTP 请求。

### M3 数据库与数据建模

**概念**：表、主键、外键、索引、事务、ACID、迁移、备份、并发写。
**项目锚点**：`tfv2/store.py`、SQLite 文件、课程/任务/讲义/笔记表。
**练习**：为“课程-资料-讲义-题目-笔记”画 ER 图；写 3 条查询。
**掌握标准**：能解释 SQLite 适合单机、不适合多用户并发写；怎么备份。

### M4 文档解析

**概念**：PDF 对象模型、文字层 vs 扫描件、页码、坐标系、渲染 DPI、PPTX/DOCX 的 XML 结构。
**项目锚点**：`tfv2/ingest/`、`source_pages.json`。
**练习**：用 PyMuPDF 提取每页文字和图片；对比同一 PDF 在 72/150/300 DPI 的差异。
**掌握标准**：能解释“为什么扫描件没有文字层”“为什么页码必须来自解析而不是模型”。

### M5 OCR 与图像

**概念**：像素、色彩空间、二值化、版面分析、文本检测/识别、公式识别、置信度。
**项目锚点**：`tfv2/ingest/mineru_backend.py`、`tfv2/product/cloud_ocr.py`。
**练习**：对一页扫描图做 OCR，记录耗时、错字、公式错误；对比云 OCR。
**掌握标准**：能解释 OCR 误差如何传播到生成内容，为什么要低置信度重试。

### M6 LLM 工程

**概念**：token、上下文窗口、temperature、system/user、结构化输出、幻觉、重试、限流、成本、缓存。
**项目锚点**：`tfv2/authoring/lecture.py`、`tfv2/llm/`。
**练习**：给同一页资料写 3 版 prompt，比较“空话率、页码引用率、耗时”。
**掌握标准**：能解释为什么“让模型写得好”不如“让坏结果无法通过”。

### M7 质量工程与评估

**概念**：单元测试、集成测试、黄金集、覆盖率、回归、门禁、可观测性。
**项目锚点**：`tfv2/quality/`、`tests/`。
**练习**：构造 5 份坏资料（空页、乱码、超长、扫描、公式），看系统如何失败。
**掌握标准**：能解释结构/内容/覆盖/PDF 四类门禁分别抓什么。

### M8 并发与任务系统

**概念**：线程 vs 进程、GIL、线程池、队列、超时、取消、重试、幂等。
**项目锚点**：`preview_generate.py` 的 `ThreadPoolExecutor`、任务表。
**练习**：把 8 页串行改成 4 路并行，测量加速比和失败率。
**掌握标准**：能解释为什么 I/O 密集适合线程、为什么不能无限并发。

### M9 前端

**概念**：DOM、事件、状态、路由、fetch、Promise、轮询、渲染性能、可访问性。
**项目锚点**：`web_v2/app.js`、`picker.js`、`app.css`。
**练习**：只读入口函数，画出“点击生成”到“进度条更新”的调用链。
**掌握标准**：能解释前端状态与后端任务状态如何同步、失败如何提示。

### M10 桌面与打包

**概念**：WebView、进程模型、资源路径、动态库、代码签名、公证、安装器。
**项目锚点**：`desktop.py`、`TermFinale.spec`、`installer/TermFinale.iss`。
**练习**：从零打一个最小 PyInstaller 应用，再包成安装器。
**掌握标准**：能解释为什么打包后路径会变、为什么要 `sys._MEIPASS`、为什么会有 SmartScreen。

### M11 DevOps 与发布

**概念**：Git 分支、语义化版本、CI 矩阵、缓存、artifact、Release、回滚。
**项目锚点**：`.github/workflows/`、`docs/index.html`。
**练习**：给一个仓库加三平台测试 + Release 上传。
**掌握标准**：能解释从 tag 到安装包的完整流水线。

### M12 产品、许可与表达

**概念**：用户旅程、失败设计、隐私边界、AGPL、成本模型。
**项目锚点**：`README.md`、`docs/ARCHITECTURE.md`、下载页。
**练习**：5 分钟讲清“为什么不是套壳 AI”，录音回听。
**掌握标准**：能让非技术听众听懂价值，让技术面试官追问不崩。

## 3. 六个月节奏

| 阶段 | 周 | 重点 | 产出 |
|---|---|---|---|
| 基础 | 1–6 | Python、HTTP、Git、SQL | 能独立跑通并画请求时序图 |
| 后端 | 7–12 | FastAPI、SQLite、任务系统 | 能解释每个 API 和表 |
| 文档 | 13–18 | PDF/PPTX/DOCX、OCR | 能处理 5 种真实资料 |
| AI | 19–24 | Prompt、结构化输出、评估 | 能做 A/B 对比和失败分析 |
| 交付 | 25–28 | 测试、CI、打包、签名 | 能独立发一个版本 |

每周固定节奏：

- 2 小时读官方文档（不是博客）
- 4 小时读代码 + 写注释/图
- 2 小时做小实验（改一个参数、跑一组对比）
- 1 小时写学习笔记（问题 → 结论 → 证据）
- 每 4 周做一次 10 分钟讲解，录音

## 4. 三遍读码法

1. **第一遍看入口**：`desktop.py` → 路由表 → 前端入口，只画调用关系，不看细节。
2. **第二遍跟一条请求**：上传一份 PDF，跟到 `source_pages.json`，记录每步输入输出。
3. **第三遍改一个小功能**：加一个“页数统计”或“导出 Markdown”，跑测试，提 PR。

不要从 `app.js` 第一行读；先搜函数名和路由。

## 5. 面试题库（按层）

**基础**
- 进程和线程区别？GIL 对这个项目有影响吗？
- UTF-8 和 GBK 区别？为什么 Windows 会乱码？

**后端**
- 为什么用 FastAPI 而不是 Flask/Django？
- 任务为什么要异步？怎么取消？崩了怎么恢复？
- SQLite 并发写会怎样？怎么备份？

**文档**
- PDF 文字层和扫描件区别？DPI 怎么选？
- 为什么 PPTX 转 PDF 会丢版式？怎么兜底？

**AI**
- 怎么防幻觉？页码引用怎么验证？
- temperature 对讲义有什么影响？
- token 成本怎么估？30 页大概多少钱？

**质量**
- 门禁不过怎么办？会不会误杀？
- 878 个测试怎么保证不是“假绿”？

**交付**
- PyInstaller 打包后路径为什么变？
- macOS 为什么需要签名/公证？
- AGPL 对你意味着什么？

## 7. 判断自己学会的标准

不是“看完了”，而是能：

1. 不看代码画出上传→生成→阅读的时序图
2. 解释每一个质量门禁抓什么、误判在哪
3. 用 3 句话说明为什么比直接问 AI 强
4. 独立修一个跨层 bug（前端→API→存储）
5. 独立打一个包并解释体积/签名/更新

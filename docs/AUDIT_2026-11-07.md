## 1. P0：发布阻断

### A. 工程与数据安全

**A1. 代码未入库，且服务端依赖未跟踪文件** ✅
- `git status`：40 项变更，13 个 `??`，`main` 领先 `origin/main` **102** 个提交。
- 未跟踪但被 import：`core/quality/constraints.py`、`core/quality/gate.py`（`server/app.py`、`services/*` 直接引用）、`core/material_kind.py`、`core/lang_convert.py`、`web/review_plan.html` 等。
- 远端 `Shuai-Lin2006/TermFinale` 只有 Initial commit + 74 字节 README；0 release、0 CI run；README 的下载链接是死链。
- 影响：一次 clean checkout 就 ImportError/页面 404；无法回滚、无法发布、无法开源。
- 修法：`git add` 全部依赖文件（node_modules 不入库）→ 本地 commit → 跑全量测试 → 推分支/tag → Release 上传 zip。

**A2. 数据库没有备份，且“拷 .db 即备份”是错的** ✅
- `term_finale_pro.db` 仅 **4096 B**，`-wal` **3.6 MB**；单独拷 .db 得到空库。
- 全仓无 backup/restore 入口；`paths.migrate_legacy` 只 `copy2` 主 db，不处理 -wal/-shm。
- 影响：一次 WAL 丢失/损坏 = 47 门课、368 个生成物全没。
- 修法：退出/定时 `PRAGMA wal_checkpoint(TRUNCATE)`；`/api/backup` 用 sqlite backup API 落 `data_dir/backups` 并轮转；`/api/restore` 先备份当前库；迁移用 backup API。

**A3. 本地 API 零鉴权 + CORS `*`** ✅
- `server/app.py` `allow_origins=["*"]`，60+ 接口无 token；`/api/settings/keys` 可改 Key，`/api/jobs` 可烧额度，`/api/reset` 可清库。
- 仅绑定 127.0.0.1 挡不住浏览器；恶意网页可发请求。
- 修法：启动生成一次性 token，中间件校验；CORS 白名单只允许自身 origin；拒绝非本地 Origin；前端所有 fetch 带 token。

**A4. `/api/reset` 会删原始上传资料** ✅
- 无条件 `unlink(material.file_path)`；旧版 Tk 导入是“引用原路径”，现库存量里就有 `~/Desktop/...pdf`。
- 影响：违反“不删原资料”，叠加 A3 可被任意网页远程触发。
- 修法：只删 `data_dir()/uploads` 与 `outputs` 下的文件；reset 前强制备份；要求 `{"confirm":"DELETE-ALL"}`；前端二次确认（当前按钮还是死的，见 D3）。

**A5. 一个坏 `exam_date` 打死所有课程接口** ✅
- `_course_dict` 每次 `date.fromisoformat`，无 try；PATCH 写入零校验。
- 影响：用户手误或远程 PATCH 一个坏值 → `/api/courses`、`/overview`、课程页永久 500，无法自救。
- 修法：写入口 400；读侧 try/except 回退 `days_left`。

**A6. 生产路径没有日志/崩溃钩子** ✅
- `setup_logging()` 只在 `main.py:164`；发布走 `desktop.py`/`server/app.py`，日志目录为空；
- 生成失败时用户只看到 `type: message`，无法诊断。
- 修法：服务启动最前面 `setup_logging()` + 异常钩子；job 失败落 `debug/`；设置页“导出诊断包”。

**A7. 取消是假取消，重启即丢，重复提交覆盖文件** 🔍
- cancel 只置标志；线程继续跑到结束并把状态改回 done、写文件；extract 池后还有 13 次补跑完全不看 stop。
- JOBS 纯内存，重启即 404；输出名只到分钟，重复提交同分钟覆盖。
- 修法：终态化检查、`cancel_futures=True`、补跑加 stop、jobs 表 + resume、文件名加秒/任务 id、同任务去重。

### B. 内容可信

**B1. 覆盖率是假的（最严重的内容问题）** ✅
- `review_service.py` 的 `coverage = ok_chunks/chunks`；分母是“解析后幸存的页”，不是总页数；`server/app.py` 把它当页覆盖率展示。
- 实证 `debug/20261107_054752_extract.json`：`pages=172, pages_cited=106, chunks_ok=40/40, coverage=1.0`（171 页 PDF，65 页从未被引用）。
- 85 页 PPT：`pages=78, cited=74, coverage≈1.0`。
- 影响：产品核心承诺“覆盖可证明”是假的，用户看到的 100% 是块覆盖。
- 修法：解析层返回总页数；逐页 ledger `{n,status,reason}`；coverage=`cited∩ledger/total`；≤150 页 <98% 判失败并逐页列出缺页。

**B2. 解析器直接丢页** ✅/🔍
- PDF：只有整本文字 <50 字才 OCR；混合扫描件里的纯图页直接不 append（`parser.py:445,477-480`）。
- PPTX：只遍历顶层 shapes，Group/OLE 里的文字和图片全丢（`parser.py:385-405`）；满版图 `ratio>0.65` 被当背景跳过。
- 85 页实测：77 条，缺 `[58,59,64,65,72,74,78,84]`；这 8 页全是 Group/OLE，soffice 转出的 PDF 里其实有文字（78 页 341 字）。
- 修法：按页判定 OCR；空页写占位；递归处理 Group；满版图单独兜底；回填后按页码排序。

**B3. 85 页回填从不执行（`ext` 被遮蔽）+ 缓存钉死** ✅
- `parser.py:409` `for _area, blob, ext in candidates[:2]` 覆盖外层 `ext`，导致 `:435 if ext == 'pptx'` 永假，`_fill_missing_ppt_pages` 从未调用。
- 解析缓存 `5a42...json` 已把 77 页钉死；改代码不失效（缓存 key 硬编码 `v3`）。
- 旁证：`ocr_cache.json` 中这 8 页的渲染 md5 命中数 0/8。
- 修法：变量改名 `img_ext`；回填与扩展名解耦；缓存 key 加解析器版本；OCR 失败重试/换模型；页面 74 单独标记。

**B4. 长文档三处静默截断** ✅/🔍
- `core/exam_engine.py:14-15` 无条件 `user_content[:10000]`；1001 页实测 866,018 字符 → 只喂 1.2%（约前 12 页）；重试再砍到 3000。
- `outline.py` 只 digest 前 40 页；1001 页按现有代码模拟 → **170 章、约 340 次调用**；第 40 页后全是“补充：N–N 页”。
- `guide_service.py:49,80-86` 双资料只留 15 页；`page_limit` 是“丢弃后半本”而不是分册。
- 修法：map-reduce（页/章摘要→汇总→回填页码）；>150 页走章节概览；不静默切片，未覆盖页明确列出；预算上限。

**B5. 页码校验对含【】文件名整体失明** ✅
- `constraints.py:36` `【[^】]*?第 N 页】` 无法跨过文件名里的 `】`；实测 `source_pages("【《有机化学【蜂考系统课】.pdf》第 5 页】") == set()`。
- 后果：页码范围、出处、allowed_pages 全部静默关闭；171 页输出 207 个考点里 62 个无出处仍 `ok=True`。
- 修法：锚定 `》第 N 页】` 或行尾；加单测；对真实 171 页输出断言 `ok=False`。

**B6. 公式：裸 LaTeX 不检测，`<` 导致 KaTeX 跳过，reader 不转 `\(`** ✅
- 数学块在 HTML 中未转义就还原：`$v_2<v_1$` 实测 0 个 KaTeX 节点，转义成 `&lt;` 后 1 个。
- reader 的 `_render_markdown` 同样；且 reader 不做 `\(...\)`→`$` 转换，真实 extract 输出 25 处 `\(W_{\text{合}}\)` 显示成坏公式。
- 裸 `\frac`/`\sin` 任何环节都不检测。
- 修法：统一渲染前转义 `& < >`；`\(\)/\[\]` 提前规范化；`syntax_issues` 加裸命令硬检查；导出/reader/PDF 共用一套预处理。

**B7. 图片会串、会静默消失、图注缓存投毒** 🔍
- `figures.py:301` `fig_pNN_1.png` 无资料前缀 → 同课程两份 PDF 第 1 页的图互相覆盖。
- 面积 >70% 的整页图被丢；导出时文件不存在直接 `html_img=""`。
- `caption_cache` 把失败结果 `""` / `"原题配图"` 永久缓存（按图片哈希，无版本/过期），重跑也救不回。
- 修法：文件名加资料哈希前缀；整页图兜底；失败不写缓存；缓存 key 加模型/提示词版本；缺图输出占位并计数。

**B8. 试卷硬校验误杀/漏杀** ✅/🔍
- `validate_paper` 无条件要求 `# 答案与解析` → `answer_mode=forbidden` 必失败。
- `_split_answer` 要求标题无后缀，`# 答案与解析（详解）` 被误判“缺少分区”。
- 任何额外 `##`（如“考试说明”）被当“未允许题型”硬失败。
- 历史 `20261107_223509_exam` 是 8/4/3/2、总分 110；`strict_counts=True` 下 4 条硬错误 → 3 次重试整卷作废（新流程已让生成/校验共用 blueprint，但旧产物/边界仍暴露问题）。
- 修法：答案分区按 answer_mode 决定；统一标题正则；额外标题只 warn；题数不符先结构化裁剪/补齐再判。

**B9. 排除词子串误杀 + 老师重点未实现** ✅
- 实测导数定义里“极限”出现 49 次 → 字面排除判失败；文件名/引用/图注含排除词也误杀。
- 没有“页码/必考/不考/只考/基团消歧”的解析；核心差异化缺失。
- 修法：`teacher_note` 解析器；考点/标题/题目标签做白名单/黑名单硬校验，正文提及只提示；违规带行号+命中词。

**B10. 提取格式漏杀/“跳过”误删/大纲缓存解耦** 🔍
- 只认 `^### 考点：`，模型写 `## 考点：`/编号列表时 blocks=0，不报任何问题。
- 正文含“跳过推导”整章被丢；丢弃无 warnings。
- 大纲缓存只按文件+mtime+语言，不含 course/角色/页数/老师规则；复用后 `chapter.pages` 越界会整章消失。
- 修法：正则放宽 + blocks=0 硬失败；只匹配“跳过”整行；fingerprint 加约束维度；越界重建。

## 6. 执行顺序与验收门

### Phase 0：保命（1-2 天，不烧 API）

### Phase 1：内容可信（1-2 周）

### Phase 2：发布工程（1-2 周，可与 Phase 1 并行）
- 自包含壳、签名/公证、Windows、自动更新、崩溃/日志、备份/恢复、隐私/协议、AGPL/第三方声明、版本/体积、CI 构建。

# TermFinale 发布前测试流程

## 阶段 1：Mac 暴力测试（先做）

目标：找内容问题、崩溃、慢路径。不要先打 Windows 包。

### 资料矩阵（至少 5 份）
| 类型 | 建议 | 重点看 |
|---|---|---|
| 文字 PDF | 20~30 页 | 章节、公式、页码引用 |
| 扫描 PDF | 10~20 页 | OCR 质量、耗时 |
| PPT | 30~60 页 | 图片配对、解析速度 |
| Word | 1 份 | 段落、表格 |
| 图片/音频 | 各 1 份 | 转写准确率 |

### 每份资料跑
- 讲义（严格模式开）
- 考点提取
- 自定义试卷（题型合计 100）
- 逻辑分析
- 阅读器：编辑 / 搜索 / Word / PDF / 提问 / 存笔记 / 加入错题
- 练习页：判分 → 得分 → 错题本 → 记住了/忘了

### 记录表
| 资料 | 任务 | 耗时 | 状态 | QA | 问题 |
|---|---|---|---|---|---|

判定标准：
- 单任务 < 3 分钟（20 页内）
- 无报错、无空输出
- 讲义覆盖率 ≥ 80%
- 图片不堆叠、不串章
- 判分题数 > 0

## 阶段 2：修复与复测

- 只修阶段 1 记录的问题
- 每修一项，只复测对应资料与任务
- 全部通过后冻结代码，不再加功能

## 阶段 3：双平台构建

Mac：
```bash
python tools/build.py --desktop
```

Windows（Win11）：
```powershell
powershell -ExecutionPolicy Bypass -File tools\build_windows.ps1
```

## 阶段 4：Windows 实机冒烟

- 启动不闪退，打开的是新 WebView 界面
- 上传 PDF / PPT，解析成功
- 生成讲义、出题各 1 次
- 阅读器提问、导出 Word / PDF（需 Edge/Chrome）
- 关闭再开，数据还在
- 中文路径、桌面输出路径正常

## 阶段 5：小范围内测

- 先给 2~3 个熟人
- 收集：崩溃、卡住、明显错误、不会用
- 修完再给 10 人

## 发布门槛（硬标准）

- 阶段 1 矩阵全部通过
- Windows 冒烟全部通过
- 无“必现崩溃”
- README 写清 Key 配置与已知限制

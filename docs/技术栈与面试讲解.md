# TermFinale 技术栈与面试讲解

> 目标：被问到任何一层，都能说清楚“它是什么、为什么用、我怎么用、代价是什么”。
> 先说结论：不需要背每一行。新版本核心约 1.4 万行，重点读懂 8 个文件即可覆盖 80% 的提问；`main.py`、`app/`、`legacy/` 是旧版，面试不要主动讲。

## 一句话架构

**本地 FastAPI 服务 + 原生 WebView 前端 + 页账本 → 并行写作 → 质量门禁 → HTML/PDF/Word 的流水线。**

## 技术栈总表

| 层 | 技术 | 在项目里干什么 | 为什么用它 | 代价/限制 |
|---|---|---|---|---|
| 语言 | Python 3.14 | 后端、解析、生成、打包 | 生态全、迭代快 | 3.14 对 PyInstaller 支持滞后 |
| 本地服务 | FastAPI + Uvicorn | 提供 `/api/*`、静态页面 | 类型清晰、异步、自动 OpenAPI | 单机服务，不做多用户 |
| 数据校验 | Pydantic | 请求体/模型结构 | 防止脏输入 | 模型多时要维护 schema |
| 数据库 | SQLite + SQLAlchemy | 课程、任务、讲义、笔记 | 零部署、单文件、可备份 | 并发写有限 |
| 桌面壳 | pywebview | macOS WKWebView / Windows WebView2 | 复用 Web UI，体积比 Electron 小 | Windows 依赖 WebView2/pythonnet |
| 旧桌面 | CustomTkinter | 旧版 Tk 界面/兜底 | 历史兼容 | 新功能不再加 |
| 前端 | 原生 JavaScript + CSS | 学习台、阅读器、选择页 | 无构建链、加载快 | `app.js` 很大，需要模块化 |
| 公式 | KaTeX | 阅读器公式渲染 | 成熟、快 | 只认 KaTeX 子集 |
| PDF | PyMuPDF | 解析、渲染、合并、页码 | 快、API 全 | AGPL |
| PPTX | python-pptx | 原生读幻灯片文字/图片 | Windows 无 LibreOffice 也能用 | 版式不 100% 还原 |
| DOCX | python-docx | 原生读段落/表格 | 同上 | 复杂样式丢失 |
| OCR | MinerU（可选）+ pix2tex | 扫描件/公式识别 | 本地、离线 | 安装重、慢 |
| 云 OCR | DashScope Qwen-VL | 图片页逐页转文字 | 不依赖本地 OCR | 收费、需百炼 Key |
| 大模型 | DeepSeek / Qwen / Kimi | 写作、复核、出题 | 中文强、OpenAI 兼容 | 会幻觉、会重试 |
| PDF 渲染 | Playwright（Chromium/Edge） | HTML → PDF | 和网页排版一致 | 需要浏览器运行时 |
| 公式排版 | Typst（可选） | 公式转图片/排版 | 排版质量高 | Windows 包可不带 |
| 打包 | PyInstaller + Inno Setup | mac .app / win setup.exe | 一键安装 | 体积大、无签名会警告 |
| CI/CD | GitHub Actions + Pages | 三平台测试、Windows 构建、下载页 | 免费、可复现 | 国内访问不稳定 |
| 测试 | unittest | 878 项 | 无额外依赖 | 部分可选依赖测试会跳过 |
| 许可 | AGPL-3.0 | 合规分发 | 满足 PyMuPDF/MinerU | 衍生作品需开源 |

## 一次生成的完整链路

1. 前端上传资料 → `POST /api/courses/save-sources/jobs`
2. `tfv2/product/sources.py` 保存原文件，转 PDF/解析
3. 生成 `source_pages.json`（页账本：每页文字、图片、质量）
4. 前端选页 → `POST /api/artifacts/{id}/preview-selected`
5. `preview_generate.py`：
   - 缺 OCR 的页先补（MinerU → Qwen-VL）
   - 每 4–8 页一块，`ThreadPoolExecutor` 最多 4 路并行
   - `authoring/lecture.py` 调模型，要求每段带页码
   - `normalize.py` + `quality/text_clean.py` 清洗空话/公式
6. 质量门禁：结构、内容、覆盖、PDF 渲染
7. 渲染 HTML/PDF/Word，写入 artifact
8. 前端进度轮询 `/api/jobs/{id}` → 完成进阅读页

## 高频问答（背思路，不背稿）

**Q：为什么不用网页版？**
A：要读本地 PDF、做 OCR、写 SQLite、导出文件；本地优先也避免资料上传。代价是要做桌面壳和打包。

**Q：为什么每段要页码？**
A：模型会编。页码是唯一可核对的锚点；没有出处的段落会被质量门禁拦下。

**Q：为什么生成要几分钟？**
A：按页分块调模型，每块要规划+写作+重试；还要 OCR、渲染 PDF、审计。并行已经把 13 页压到约 3 分钟。

**Q：质量门禁做什么？**
A：结构（标题/块）、内容（空话/重复）、覆盖（每页有没有讲到）、PDF（公式有没有渲染失败）。任一不过，不标完成。

**Q：怎么防幻觉？**
A：限定资料页、要求引用页码、事实表逐条覆盖、失败就标“需重做”；不保证 100%。

**Q：为什么 AGPL？**
A：PyMuPDF/MinerU 是 AGPL；分发安装包必须提供源码。仓库公开即满足源码义务。

**Q：最大的技术难点？**
A：不是调模型，是“让输出可核对、可失败、可恢复”：页账本、门禁、重试、打包跨平台。

## 5 分钟演示脚本

1. 打开主控台，说明本地优先
2. 新建课程，上传一份 PDF/PPTX
3. 选 8 页，选档位/人设
4. 展示全屏进度：分块、OCR、渲染
5. 打开讲义，指一段的页码出处
6. 打开质量报告：覆盖、空话检查
7. 出 3 道题，展示解析和页码
8. 结尾讲限制：扫描件 OCR、模型波动、AGPL

# TermFinale 路线（冻结版 v6，36 轮，2026-11-14）

> 替代 v5（已存档 docs/ROADMAP_V5.md）。以后只说“做第 N 轮”，只做第 N 轮。
> v6 在 v5 基础上新增第 35 轮：自定义资料 Agent（用户自由提示词 → 结构化合同 → 任意文本型产物）。发布门禁包含长书、英文、自定义资料 Agent。

# 0. 为什么之前每轮完不成（真实原因）

1. **一轮塞太多**：第 2 轮同时做四档状态、硬/软门禁、partial 导出、断点续跑、UI 文案；断点续跑本身就是一个独立工程。
2. **验收不是可执行断言**：写“断点续跑”却没有“中断→续跑→对比”的测试；写“0 静默丢失”没有场景脚本。
3. **先写代码后补验证**：代码路径通了就以为完成，真实模型/真实产物一跑才发现缺口。
4. **真实生成太慢**：一张 18 题卷 3–17 分钟，5 张就是半小时；我把等待当成“快完成了”，实际没验收。
5. **中途加范围**：补 UI 文案、补 preview API、补 section_limit，都是“顺手”，导致本轮边界失控。
6. **环境不确定性**：Python 3.14、API 限流、任务中断、模型返回格式不稳，每次失败都要重跑。
7. **没有预检清单**：开工前没列“这轮结束必须看到哪几个文件/哪条命令通过”。
8. **遇到结构性缺口就停**：正确做法是当场把这一轮拆小，而不是留到下一轮。

# 1. 新规则（写死）

1. 每轮只做**一个主交付**；出现第二个独立功能，立即拆到下一轮。
2. 每轮开工前先写“验收命令/测试文件”；结束必须实际跑过，输出通过。
3. 每轮最多重试 2 次；仍失败，**当场拆成更小的轮次**，不进入下一轮。
4. 不把“代码写了/单测过了”当完成；必须有本轮要求的真实产物或集成测试。
5. 不临时改 UI/提示词/范围；发现缺口，记到下一轮。
6. 每轮结束给：改了什么、验收命令、结果、和上轮比提升、没做什么。
7. 轮数可以多；**每轮必须闭合**。

# 2. 每轮的“完成”定义

- 代码：改动落地，编译通过。
- 测试：本轮专属测试通过，且全量测试不回退。
- 产物：本轮要求的真实文件/接口/截图存在。
- 报告：一段可核对的验收记录。
缺一项都不算完成。

# 4. 最终验收（不变）

1. 出卷：5 张≥4 validated；覆盖≥45%；0 重复、0 自纠错、0 冲突；≤5 分钟。
2. 提取：50 页召回/准确≥85%；近重复 0；每条有引文；名词含英文/缩写；原题含年份/题号/分值。
3. 公式：20 条≥80% 可渲染；其余保图；PDF/Word 无乱码。
4. 表格：5 张≥4 张结构正确；PDF/Word 真表格。
5. 图片：插图准确≥90%，资料图召回≥70%，0 错图。
6. 讲义：24 页 Gate 通过，页覆盖 100%，padding 0，≤10 分钟，图≤页面 25%。
7. 排除：20 条准确≥95%，误删 0，四输出遵守。
8. 交付：10 场景 0 静默丢失，partial 可导出；5 张卷无全 rejected。
9. UI：重复入口 0，点击≤3，每页一个主 CTA，旧路由全重定向。
10. 基准：不低于最好开源基线 90%。
11. 长书：300 页教材≥90% 章 validated，0 静默丢章，断点续跑通过。
12. 英文：文字型英文 PDF/PPT 的提取/讲义/出卷通过，正文无中文泄漏（术语除外）。

# 6. UI 生成体验（写死，适用于第 21–26 轮）

## 6.1 生成时

- 生成开始即进入**全屏生成视图**：禁用侧栏、顶栏、课程、练习、出卷、提取等所有入口；
- 只保留一个**取消**按钮，位置固定、可点、二次确认；
- 大进度环/进度条占屏幕中心，百分比和当前步骤同时显示；
- 显示：当前步骤、第 N/M 节/题、已用时间、预计剩余（可估则估，不编）；
- 动态提示每 2–5 秒更新，不能长时间不动；后台心跳保证“没卡死”；
- 步骤切换有动画，不是一条细线；
- 取消后立即停止后续模型调用，保留已完成产物为 partial。

## 6.2 布局原则

- 禁止无意义辅助标签/说明文字堆叠；让标题、分组、间距、颜色本身表达层级；
- 一个页面只保留一个主操作；说明文字最多一句，放在需要决策的位置；
- 空状态给下一步，不给“暂无数据”死路；
- 生成视图不显示技术术语（token、审计、门限）给用户。

## 6.3 验收

- 连续生成 10 分钟，进度至少每 5 秒变化一次；
- 生成期间除取消外所有入口不可点；
- 取消后 3 秒内回到课程页，产物保留 partial；
- 1440/390 两种宽度都可用，不横向滚动。

## 7.1 执行顺序（v6）

第 11–20 轮（内容质量）→ 第 31–33 轮（长书/英文，发布阻塞）→ 第 35 轮（自定义资料 Agent，发布阻塞）→ 第 21–30 轮（UI/预发布）→ 第 36 轮（正式发布）。

## 7.2 对外承诺（发布时写死）

- 单份 50 页以内：稳定，默认推荐；
- 50–100 页：可用，提示可能更慢；
- 300–600 页：必须走“整本教材/长书模式”，按章生成、章级 validated，不再承诺“单份一次出全书”；
- 英文：只承诺文字型 PDF/PPTX/DOCX；英文扫描件/手写不在首发承诺内。

# 8. 自定义资料 Agent（第 35 轮，发布阻塞）

## 8.1 用户能写什么

- **不要求用户选模板、不要求填表、不要求用固定词。** 用户可以用一句话、一段话，甚至语音转文字的口语描述。
- 以下只是能力范围，不是必填项：
  - 目标：扩写 / 压缩 / 零基础讲解 / 考前冲刺 / 专题课 / 例题课 / 背诵版 / 双语；
  - 风格：老师、学长、口语、严谨、幽默、极简；
  - 篇幅：页数或“讲多细”；
  - 结构：章节顺序、每节必须有什么、不要什么；
  - 标准：必须覆盖的考点、必须出现的例题、必须引原文、难度；
  - 受众：基础、专业、考研/期末/补考。
- 用户说“1.5 倍”就按 1.5 倍；没说，AI 不硬套倍数，只按“讲细一点/压缩一点”理解并确认。
- **输出形态也不固定**（同一份资料）：讲义、详细答案解析、复习笔记、一页纸总结、章节提纲、对比表、背诵卡、题库、学习计划、双语对照、公式手册、术语表等文本型产物。

## 8.2 怎么保证不是“提示词越权”

- 自由提示词先由 Brief 智能体编译成结构化合同：goal / audience / style / length / structure / must_cover / must_avoid / quote_policy / standards；
- **生成前必须确认，不能直接开跑**：
  1. 用户自然语言写需求，不需要套模板；
  2. AI 只做轻量理解，不生成产物；
  3. 只有关键信息缺失/歧义时才问 **最多 3 个** 问题，能自己合理判断就不问；
  4. 展示“我理解的是……”确认卡：用用户自己的话复述，不强迫他填 6 个字段；
  5. 用户点“确认生成”才进入昂贵生成；可改任意一句话、可取消；
  6. 取消/修改不消耗生成调用，只消耗一次轻量理解。
- 生成严格按已确认合同，不直接拿原始提示词覆盖系统质量门禁；
- 资料 grounding、引文、排除、防凑数仍然生效；
- 合同冲突时明确说哪条做不到（例如“不要引用原文”与“每条有原文引文”冲突）。

## 8.3 验收

- 同一份资料，5 条**自然语言需求**（用户原话，不限定模板）：
  1. “把第 3 章讲细一点，口语化，每节带例子” → 讲义；
  2. “按章写详细答案解析，步骤要细” → 答案解析；
  3. “压成一页纸，考前看” → 一页纸总结；
  4. “做一张交感/副交感对比表” → 表格；
  5. “7 天冲刺计划，每天看什么” → 学习计划。
- 五份形态/结构/篇幅必须明显不同；用户明确说“1.5 倍”时才按倍数，没说不得硬套；
- 源文页覆盖≥98%，0 凑数，0 无来源编造；
- 用户 must_cover 清单 100% 出现；
- **模糊 brief 必须先提问；确认前不得发起讲义生成；取消不产生讲义产物**；
- 单份 ≤50 页，生成 ≤10 分钟。

## 8.4 不做

- 本轮承诺“**文本型学习产物**”任意形态；不是任意文件格式。
- 视频、音频、动画本轮不做；PPT/思维导图需要额外渲染器，放到第 35 轮之后的独立轮，不混在文本 Agent 里。
- 不承诺“不要资料也能写”；不承诺无限页数，长书仍走第 31–32 轮。

## 8.5 和长书的配合（截图场景）

用户 7 章、每章约 80 页、共约 560 页，要求“按章写详细答案解析/讲义”：

- 不按单份 560 页硬跑；按目录/章节拆成 7 个 chapter artifact；
- 每章 80 页，章内可再按 6–8 页生成、章级 checkpoint；
- 用户的需求是“全局 brief”，可对某章单独改 brief；
- 每章独立 validated，最后全书索引/跨章去重；
- 进度按章显示，中断可从章/节续跑；
- 不承诺几分钟出全书：按章跑，时间随章数增长。
